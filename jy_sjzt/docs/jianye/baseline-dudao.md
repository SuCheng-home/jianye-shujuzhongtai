## 7. 口径不明之处 ★★ 建邺迁移的最大风险区

> **本节结论一句话**：大屏上所有"被听课数量 / 被听课人数 / A课率 / 满意度"数字，**在原版里全部是硬编码的展示值，仓库内不存在任何可以重新算出它们的结构化数据源**。
> `xuanwu-zonghe-data.js`（652KB）里**只有综合督导报告档案**，没有一条听课记录、没有一条问卷作答。
> 因此建邺若缺这些数据，**必须新建数据源**，而不是"用别的指标顶替"。

### 7.1 「视导记录条数」是否等于「被听课节数」？→ **不等于，且两者都无法从原数据算出**

| 概念 | 原数据里有什么 | 结论 |
|---|---|---|
| **视导记录条数** | 主屏 `ACTS` = **7 行**（活动级：活动名/学校/日期/A课率）；`ZH_DATA.records` = **12 行**（综合督导批次级） | 这是**活动/批次计数**，粒度是"一次视导去了一所学校" |
| **被听课节数** | 主屏 `校内听课 1386 节` + `视导听课 926 节` = 2312 节；`STAGE_STAT.听课数量` = 986+730+596 = 2312 节 | 这是**课次计数**，粒度是"一节课" |

- **两者量级完全不同**：7 次活动 vs 2312 节课。**不能用记录条数冒充节数。**
- **交叉验证**：`ZH_DATA` 里 12 次综合督导，从报告正文可提取的听课节数合计 = **811 节**（樱花 78、长江路 80、中央路 75、月苑一小 92、海英 54、紫金山 56、科利华紫金 48、锁金二小 49、北小 94、南农实小 78、铁北新城 69、同仁 38）。**811 ≠ 926（视导听课）≠ 2312（合计）**，说明主屏数字**不来自** `ZH_DATA`。
- **原数据无"课次级"记录表，建邺必须补。** 要支撑"被听课节数"，最小需要一张课次表：`课次ID / 活动ID / 学校ID / 授课教师ID / 学科 / 上课日期 / 课等级(A|B|C|D) / 听课来源(校内|视导)`。

- [ ] **验收 7.1.1**：建邺版**明确区分**"视导活动条数"（活动级）与"被听课节数"（课次级），**不得**用前者填充后者。
- [ ] **验收 7.1.2**：建邺版提供**课次级数据源**，或在页面上明确标注该指标"原数据无此字段，建邺必须补"并给出取数口径说明。

### 7.2 校内听课 vs 视导听课 靠哪个字段区分？→ **原数据无此字段，建邺必须补**

- **实测结论**：全库搜索 `校内听课`，命中 **2 处，且都是 UI 文案/CSS 注释**：
  - `xuanwu-shuzhi-dudao.html:419` 面板标题 `校内听课和视导听课情况`
  - `xuanwu-shuzhi-dudao.html:423` 分组标签 `<span class="kg in">校内听课</span>`
  - `xuanwu-shuzhi-dudao.html:96` CSS 注释 `/* ===== 校内/视导听课 分组指标 ===== */`
- **没有任何数据字段、枚举、标志位区分这两类听课。** `ZH_DATA`、`ZX_DATA`、`ZX_DETAIL`、`ACTS`、`COURSE`、`SCHOOLS` 里都没有"听课来源/听课类型"这一维。
- 6 个数字（1386 节 / 208 人 / 88%、926 节 / 142 人 / 93%）**全部硬编码在 HTML 的 `data-cnt` 属性里**（第 424–426、430–432 行）。
- 唯一可推断的语义线索：主屏 `ACTS` 的活动类型有 4 种 —— `集中视导` / `常态好深随机视导` / `专项视导` / `专项检查`。这些是**区级视导**的活动类型；"校内听课"按业务常识应是**学校内部（行政/教研组长）听课**，与区级视导相对。**但这只是推断，原数据未做任何标注。**

> **原数据无此字段，建邺必须补**：需要一个 `听课来源` 维度（至少二值：`校内` / `视导`），落在课次级记录上。

- [ ] **验收 7.2.1**：建邺版有明确的 `听课来源`（校内 / 视导）字段与取数口径文档。
- [ ] **验收 7.2.2**：**两组共 6 个指标全部保留**（校内 3 个 + 视导 3 个），**不得**因缺"校内"数据而只保留"视导"一组、更不得合并成一组。
- [ ] **验收 7.2.3**：若建邺确实拿不到"校内听课"数据，**必须**在这 3 个指标位显示 `—` 并在交付说明中写明"原数据无此字段，建邺必须补"，**不得**用其他数字填充、**不得**删除指标位。

### 7.3 被听人员有没有唯一标识可供去重？→ **原数据完全没有，建邺必须补**

- **`被听课人数`**（校内 208 人 / 视导 142 人 / 各学段 189·107·54 人 / 小学页 605 人）**全部是硬编码数字**，仓库内**不存在任何教师级的听课记录**，因此：
  - **没有教师 ID、没有姓名、没有工号** —— 无法去重，也无法验证 208/142 这两个数是怎么来的。
  - 无法回答"同一位教师被听了 3 节算 1 人还是 3 人"。
- **全库唯一的教师级明细**是 `ZX_DETAIL` 的**教案抽查表**（265 行，含 `姓名` + `学科`），但：
  - 它是**专项督导的教案（备课本）检查名单**，**不是被听课教师名单**；
  - 它**只有姓名，没有 ID**，实测 265 行对应 **264 个不重复姓名**（存在 1 例重名/跨校），**靠姓名去重不可靠**；

### 🔴 P0 —— 极可能被静默缩水的地方

**坑 1｜「满意度题目分析」是全大屏最脆弱板块。**

### 11.2 建议的验收顺序

1. **先验结构与链路**（第 1、5 节）—— 数面板、数页面、点每一条链接。最快、最能暴露"砍页面/砍板块"。

   - 主屏 `ZX_MAIN` 校名集合 == 专项 `ZX_DATA` 校名集合，且总分 == 四项之和
   - 主屏 `SAT_TOTAL` 9 值 == 三学段子页 9 个满意度 KPI
